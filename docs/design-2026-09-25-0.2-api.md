# Design: geoexp 0.2.0 — budget, panel preparation, plots, aggregation

Status: **accepted** 2026-09-25 by the maintainer, section by section.
Builds on `docs/design-2026-09-05-v0.5-api.md`; nothing accepted there changes
behaviour here.

Scope, per the version map in `CLAUDE.md` (0.2.x = budget-constrained
selection), plus three usability features pulled in alongside it:

| Feature | Public surface | Oracle parity |
|---|---|---|
| Budget-constrained selection | `rank_designs(..., budget=)`, `investment_mde` column, `DesignRanking.within_budget()` | **Yes** — `GeoLiftMarketSelection(budget=)` |
| Panel preparation | `prepare_panel()` | **Yes** — `GeoDataRead` |
| Design plots | `DesignRanking.fit_path()`, `.plot_power()`, `.plot_fit()` | No — presentation; excluded, §6 |
| Aggregation to coarser units | `Hierarchy`, `aggregate_panel()` | No — GeoLift has none; excluded, §6 |

Ready-made hierarchies (IBGE first) ship in a **separate package,
`geoexp-units`**, described in §5.

## Maintainer decisions recorded here

`CLAUDE.md` reserves some decisions for the maintainer. Each was taken
explicitly in the design conversation of 2026-09-25:

1. **New dependency** — `matplotlib`, as an optional extra `geoexp[plot]`,
   imported lazily. Chosen over a hard dependency (weight on pipelines that
   never plot), plotly (heavy, off-style for static reports) and data-only
   helpers (users asked for plots).
2. **Public API changes** — new exports `prepare_panel`, `Hierarchy`,
   `aggregate_panel`; new parameter `budget` and new methods on
   `DesignRanking`. No existing behaviour changes.
3. **New exclusions** from the parity rule — plots, `Hierarchy` /
   `aggregate_panel`, and the `prepare_panel` options with no `GeoDataRead`
   counterpart (`every`, `on_incomplete="fill_zero"`). Recorded in
   `docs/geolift-oracle-characterization.md` §6 with reasons.
4. **Ready-made hierarchies live outside geoexp**, in `geoexp-units` (name
   chosen over `geounits`, `geoexp-regions`, `unitmaps`). geoexp defines the
   contract; the companion ships data.

## 1. Budget

### What the oracle does (measured 2026-09-25, black box)

Same call as the characterization §3, with and without `budget`:

- `BestMarkets.EffectSize` is the smallest grid effect whose power reaches
  0.8 — geoexp's `mde_grid`.
- `BestMarkets.Investment = cpic × EffectSize × Σ Y_treated` over the
  treatment window (formula already verified in §5).
- `budget = b` keeps the rows with `Investment ≤ b` and **re-ranks** them
  1..n (15 of 30 kept at `b` = median investment).
- Two identical calls without `budget` differ in 3 of 180 `PowerCurves`
  cells, all at the decision boundary with identical `AvgATT`. The oracle is
  not deterministic between calls; an apparent `budget` effect on the curves
  is that noise, not semantics.

### Surface

- When `cpic` is given, a new column
  `investment_mde = cpic × mde_grid × Σ Y_treated`; null when `mde_grid` is
  null. The existing `investment` column (at `target_effect_size`) keeps its
  meaning. *Amended during implementation:* parity showed GeoLift averages
  `Σ Y_treated` over the lookback windows, which 0.1.0 had verified only at
  `lookback_window = 1`; both columns now use that average, so `investment`
  values change for `lookback_window > 1`. Recorded as a fix in the CHANGELOG
  and in the characterization §5 — **needs the maintainer's sign-off as a
  behaviour change.**
- **Why the grid MDE, not the interpolated one:** `mde_grid ≥ mde` always, so
  the cost is an upper bound — a design that passes the budget can afford the
  lift it can detect. It is also exactly GeoLift's `Investment`, so parity is
  exact.
- `rank_designs(..., budget=b)` requires `cpic` (`ValueError` otherwise),
  drops rows with `investment_mde > b` or null, and re-ranks.
- `DesignRanking` keeps the unfiltered frame privately.
  `res.within_budget(b2)` returns a new `DesignRanking` filtered from the
  unfiltered frame, so a budget can be tightened *or* loosened without
  recomputation. `res.power()` keeps working for every candidate.
- Nothing fits → empty ranking plus a `UserWarning` naming the cheapest
  `investment_mde` available.

### Required fix carried by this release

`_summarize` computed the treatment window as `time > max(time) - duration`,
which assumes an integer time column. `prepare_panel` keeps real dates by
default, and augsynth-py accepts them (verified), so the window becomes **the
last `duration` distinct periods**. Identical on integer panels; correct on
dates.

### Parity

Same R call with `budget` on both sides:

- `investment_mde` vs `BestMarkets.Investment`, exact, on rows where the two
  grid MDEs coincide;
- the kept candidate set, within the noise-floor tolerance of §7.3 — not
  strict equality, because the oracle flips boundary cells between calls.

## 2. `prepare_panel`

### What `GeoDataRead` does (measured 2026-09-25, black box)

On a copy of `GeoLift_PreTest` with four injected defects:

| Defect | Behaviour |
|---|---|
| `"Atlanta"` vs `"atlanta"` | lower-cased |
| Duplicate unit × date row | **summed** (2610 + 1 → 2611) |
| One missing date for a unit | **whole unit dropped** |
| One `NA` outcome for a unit | **whole unit dropped** |

Dates are parsed with an explicit `format` and replaced by an integer `time`
1..T. There is no temporal aggregation (no `period` argument). Drops are
reported only in an optional summary.

This corrects the characterization §2, which said geoexp "must not
reimplement `GeoDataRead`". That rule protected the *parity harness* — which
still feeds the R-converted panel to both sides — not the package.
Implementing behaviour measured from outputs is not translating source.

### Surface

```python
prepare_panel(
    data, *, unit, time, outcome,
    date_format=None,        # strftime; None = polars inference
    normalize_units=True,    # strip + lower-case string units
    on_duplicate="sum",      # or "raise"
    on_incomplete="drop",    # or "fill_zero", "raise"
    every=None,              # e.g. "1w": temporal aggregation by sum
    time_index=False,        # True: integer 1..T replaces the date
) -> pl.DataFrame            # exactly [unit, time, outcome], sorted
```

Order of operations: parse time → normalize units (a warning names any
names that merged) → sum duplicates → aggregate with `every` (partial edge
periods dropped with a warning — a truncated last week biases the last
point) → incomplete units (universe = union of observed periods; `drop`
warns with the units and the reason) → `time_index`.

`on_incomplete="drop"` is the default: GeoLift's result, but loud.

### Parity

A dirty fixture with the four defects above is built in R and handed
identically to `GeoDataRead` and `prepare_panel(time_index=True)`; frames
must be equal.

## 3. Plots

`DesignRanking` keeps the ranking context privately (panel reference,
prototype estimator, column names).

- `res.fit_path(candidate, duration) -> pl.DataFrame` with
  `[time, actual, synthetic, gap, window]`. Fits a **copy** of the prototype
  estimator (never mutated) with the simulated test in the last `duration`
  periods. No matplotlib needed. Uses only the documented fitted attributes
  `periods_`, `actual_`, `synthetic_`, `pre_mask_`.
- `res.plot_power(candidate, *, ax=None)` — power vs effect size, one line
  per duration, reference at `target_power`, marker at `mde`.
- `res.plot_fit(candidate, duration, *, ax=None)` — actual vs synthetic,
  test window shaded, `rmspe_pre` annotated.

Both return the `Axes`. Missing matplotlib raises `ImportError` naming
`pip install geoexp[plot]`. Tests use the Agg backend and assert on line
data, not pixels.

## 4. `Hierarchy` and `aggregate_panel`

```python
Hierarchy.from_frame(frame, *, levels, labels=None, name, source=None)
aggregate_panel(panel, *, unit, time, outcome, hierarchy, to,
                from_level=None, on_unmapped="raise", use_labels=False)
```

- A `Hierarchy` is one row per finest unit, one column per level, optional
  label columns (`{"uf": "uf_sigla"}`). Construction validates only no nulls
  and a unique finest level.
- **Nesting is not required.** The check that matters runs at aggregation:
  every `from_level` value must map to exactly one `to` value. That admits
  non-nesting hierarchies (media markets crossing states) with no special
  case.
- `aggregate_panel` returns `[to, time, *outcome]`, summed. `outcome` takes
  several columns because rates aggregate as numerator and denominator; the
  docs say so rather than offering a wrong mean.
- Unmapped units raise by default (with a sample); `"drop"` warns. A dtype
  mismatch between panel and hierarchy keys raises with that specific hint
  instead of an empty join.

## 5. `geoexp-units` (companion package, separate repository)

- `geoexp_units.br.ibge()` returns a `Hierarchy`:
  `municipio → regiao_imediata → regiao_intermediaria → uf → regiao`; labels
  for names and UF abbreviation. Keyed by the 7-digit IBGE code.
  *Amended during implementation:* the legacy `microrregiao`/`mesorregiao`
  were frozen in 2017 and do not cover municipalities created since (one in
  the 2026-09-25 snapshot), so they are a separate `ibge(legacy=True)` that
  leaves those out with a warning, instead of levels of the same hierarchy
  (which forbids nulls).
- Labels are only usable where they identify units: `use_labels=True` raises
  on homonyms (two regiões imediatas are called "Itabaiana") rather than
  summing them together.
- Data: a CSV under `data/br/` with provenance and extraction date,
  regenerated by `scripts/fetch_ibge.py` (standard library only).
- `geoexp_units.available()` / `geoexp_units.load("br.ibge")` over a plain
  registry. A new country is a module, a CSV and one registry line.
- Depends on `geoexp>=0.2`; geoexp does not depend on it.

Deferred: matching by municipality *name* (accents, homonyms across states)
and neighbour maps for spillover exclusion.

## 6. Testing

| Feature | Unit (no R) | Parity (rpy2) |
|---|---|---|
| Budget | `investment_mde`, filter + re-rank, `within_budget` both ways, empty + warning, `budget` without `cpic`, date-time window | `investment_mde` exact; kept set within noise floor |
| `prepare_panel` | each step in isolation, name collisions, `every` edges, `fill_zero`, `raise` | dirty fixture vs `GeoDataRead`, exact |
| `Hierarchy` / `aggregate_panel` | non-functional mapping, dtype mismatch, unmapped, labels, multi-outcome | excluded |
| Plots | `fit_path` (copy, windows), Axes line data, friendly `ImportError` | excluded |

CI installs the `plot` extra; one job runs without it to cover the
`ImportError`.

## 7. Not in this release
